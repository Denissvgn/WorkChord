# WorkChord 1.11.0

Version 1.11.0 follows the 1.10.0 release. It lets work be stopped without being canceled
(a new `postponed` status), records work that was replaced by a successor that already
shipped, and lets an owner accept resolved work with a recorded reason under the
different-publisher review policy. It also adds routing controls for model catalogs
(effort, a free or local preference, deployment-declared qualification keys and a
calibration contract), keeps a task's routing and reviewer consistent when it is reassigned,
and makes several scheduling, import and onboarding paths more predictable.

The notes below group the changes by outcome. Pull request numbers link to the change on
GitHub.

## What changed for people

### Stop work without canceling it

A task can now be postponed. Postponing stops planned, active or resolved work, records why,
and records what has to be true before it resumes. A requirement can be that another task is
accepted or resolved, that a triage item is resolved, that a date arrives, or that the owner
decides. ([#153](https://github.com/Denissvgn/WorkChord/pull/153))

- Work returns on its own when the last requirement holds: to Planned, or to Resolved if it
  was postponed after resolution. A date requirement holds on that date in the project's
  time zone. Only a signed-in workspace owner can record an owner decision; project
  managers, agents and other operators cannot.
  ([#162](https://github.com/Denissvgn/WorkChord/pull/162))
- Postponed work is left out of scheduling, capacity, readiness, dispatch and verifier
  selection. It keeps its last dates as history and frees its assignee's days. A task that
  waits on postponed work is reported with the reason `predecessor_postponed` and the
  postponed tasks it is waiting on. ([#163](https://github.com/Denissvgn/WorkChord/pull/163))
- On the task page, owners and project managers can postpone a task with a reason and
  requirements, see what postponing releases before they confirm, and reactivate it. A
  postponed task shows each requirement as met or not met yet.
  ([#164](https://github.com/Denissvgn/WorkChord/pull/164))

### Replaced work is recorded, not reopened

When a successor task was already executed and closed or accepted before anyone recorded a
replacement, the original can now be superseded. The original keeps its history and progress,
nothing reopens, and the deliverable is not counted twice. A postponed original has its
postponement closed in the same step.
([#167](https://github.com/Denissvgn/WorkChord/pull/167))

Canceled and superseded tasks are now reported as their own terminal states in task
responses, counts and filters, instead of showing the status they had when they were
withdrawn. A task replaced through either path is labeled `superseded` and links to its
successor. ([#171](https://github.com/Denissvgn/WorkChord/pull/171))

Tasks, My Work, the Board, Gantt, Analytics and the release and iteration summaries show
postponed, canceled and superseded work with their own written labels and icons, and each can
be filtered. The Board keeps them in collapsed lanes rather than in a column, the Gantt never
draws them as scheduled work, and progress totals report the three counts. My Work lists
stopped work apart from the work you can act on. The task page has a Supersede form for owners,
operators and project managers. ([#177](https://github.com/Denissvgn/WorkChord/pull/177))

### Owner acceptance and manual provenance

With the different-publisher review policy on, an owner or operator can accept resolved work
with a required reason, without switching the policy off for the project. The task page offers
Accept as owner, and a Review history list labels an owner override. An agent, the operator
key, a project manager or reviewer, and a browser with no signed-in person cannot use it.
([#152](https://github.com/Denissvgn/WorkChord/pull/152),
[#159](https://github.com/Denissvgn/WorkChord/pull/159))

Work that was implemented and merged outside recorded runs can now get an independent review.
An owner, operator, project manager or the project's PM agent records who executed it and
the commits or pull request, and the record is checked against the same attribution rules
as a review verdict. ([#160](https://github.com/Denissvgn/WorkChord/pull/160))

Every verification or review refusal now names the next legal step: who can take it, the
route and tool, and the task page action when there is one.
([#173](https://github.com/Denissvgn/WorkChord/pull/173))

### Reassigning a task

A task's first model, escalation steps and reviewer are now stored as structured routing and
shown in a Routing section on the task page. Reassigning a task checks that routing against the
new assignee and the project's review policy. A project can refuse a conflicting
reassignment (the default) or only warn. The server suggests a consistent first step and
reviewer, which can be applied in the same save.
([#175](https://github.com/Denissvgn/WorkChord/pull/175))

When you reassign from the task page, "Reassign to" shows the conflicts and the suggested
reviewer before anything is saved, including a same-publisher reviewer, and offers a
replacement. ([#176](https://github.com/Denissvgn/WorkChord/pull/176))

### Scheduling and planning

- A schedule run keeps the saved dates of every task it could not place, instead of clearing
  them and leaving the task unable to start. Kept tasks are listed with their reason in a
  `kept_dates` list on the result; only a half-dated task has its dates cleared.
  ([#156](https://github.com/Denissvgn/WorkChord/pull/156))
- An assignee's free days are used for ready work before a higher-priority task that has to
  wait for its prerequisite, so the assignee is not idle.
  ([#170](https://github.com/Denissvgn/WorkChord/pull/170))
- Setting a milestone no longer makes a queued or accepted assignment stale.
  ([#161](https://github.com/Denissvgn/WorkChord/pull/161))
- A plan import can be previewed under planning scope before it is applied: the dry run
  returns the exact tasks, dependencies, links, dates and team members the file would
  create, change or remove. ([#166](https://github.com/Denissvgn/WorkChord/pull/166))
- An intake whose source link points at this instance, such as a link to one of its pages, now
  converts to a task, and the link is stored as a relative path. Private, link-local and
  reserved addresses, other schemes and embedded credentials are refused with the named code
  `intake_source_link_not_allowed`. ([#150](https://github.com/Denissvgn/WorkChord/pull/150))

### MCP tools and REST routes

New MCP tools, each calling the same service as its REST route:

- `agent_postpone_task`, `agent_reactivate_task` and `agent_get_task_postponement`. The owner
  decision is deliberately not an agent tool.
  ([#165](https://github.com/Denissvgn/WorkChord/pull/165))
- `agent_record_manual_provenance` ([#160](https://github.com/Denissvgn/WorkChord/pull/160)).
- `agent_preview_iteration_import`, read-only, under `planning:write`
  ([#166](https://github.com/Denissvgn/WorkChord/pull/166)).
- `workspace_list_project_tasks` takes an optional `status`, including `postponed`,
  `canceled` and `superseded`.

New REST routes:

- `POST /api/tasks/{task_id}/postpone`, `POST /api/tasks/{task_id}/reactivate`,
  `GET /api/tasks/{task_id}/postponement` and the owner-decision route
  `POST /api/tasks/{task_id}/postponement/requirements/{requirement_id}/decision`
  ([#153](https://github.com/Denissvgn/WorkChord/pull/153),
  [#162](https://github.com/Denissvgn/WorkChord/pull/162)).
- `POST /api/tasks/{task_id}/owner-acceptance`
  ([#152](https://github.com/Denissvgn/WorkChord/pull/152)).
- `POST /api/tasks/{task_id}/manual-provenance` and the planning-scope form of it
  ([#160](https://github.com/Denissvgn/WorkChord/pull/160)).
- `POST /api/tasks/{task_id}/supersession`
  ([#167](https://github.com/Denissvgn/WorkChord/pull/167)).
- `POST /api/agent/planning/iterations/{iteration_id}/import/dry-run` and
  `POST /api/agent/planning/iterations/import/dry-run`
  ([#166](https://github.com/Denissvgn/WorkChord/pull/166)).
- `GET /api/tasks/{id}/routing/check` and an `assignee_id` check before reassignment
  ([#175](https://github.com/Denissvgn/WorkChord/pull/175)).
- `GET /api/projects/{id}/tasks?status=` and `GET /api/tasks/lookup?task_status=` accept
  `postponed`, `canceled` and `superseded`; `leaf_only` on lookup leaves out parents.

Task responses add `displayed_state`, `successor_task_id` and `successor_kind`. Iteration,
project, milestone, portfolio and release summaries add `canceled_tasks` and `superseded_tasks`,
and `status_counts` gains `canceled` and `superseded`. Withdrawn work stays outside the
total and every other bucket. Check the current API schemas when you update a client.
([#171](https://github.com/Denissvgn/WorkChord/pull/171))

### Onboarding and verifier readiness

The team onboarding handoff now names a runtime instance (`runtime_instance_id`), the
acknowledgement returns it, and team status shows when a different runtime took over a seat.
Acknowledgements recorded earlier remain valid and read as identity unknown. A runtime that
advertises the `runtime-instance-identity-v1` server feature must send the identity.
([#155](https://github.com/Denissvgn/WorkChord/pull/155))

A verifier is now judged by its own presence. A refusal says which actors are not ready, since
when, and the staleness limit, instead of requiring every declared actor to be present.
([#168](https://github.com/Denissvgn/WorkChord/pull/168))

A recovery requeue now works when model-aware routing is off or in shadow mode: it starts as a
supervised recovery, or is refused with `recovery_supervision_unavailable` and the condition
to fix. It was previously left unable to begin.
([#157](https://github.com/Denissvgn/WorkChord/pull/157))

### Connectors

Claude Code and Antigravity now have generated role adapters next to the Codex one, built from
the same role packages and linked from the connect instructions.
([#154](https://github.com/Denissvgn/WorkChord/pull/154))

## What changed for operators

### Model catalog and routing

- **Effort.** A catalog entry records its reasoning effort (`unknown`, `low`, `medium`,
  `high`, `xhigh` or `max`). A task can require a minimum effort; a candidate with lower or
  unknown effort is excluded, and among the rest the lowest sufficient setting ranks first.
  Without a stated requirement, effort changes nothing.
  ([#158](https://github.com/Denissvgn/WorkChord/pull/158))
- **Free or local first.** An entry can be marked `local_first`. At equal adequacy it ranks
  first, even ahead of a lower cost tier. It never overrides a hard blocker or an adequacy
  difference. ([#151](https://github.com/Denissvgn/WorkChord/pull/151))
- **Qualification keys.** An operator can declare, revise and retire deployment-specific
  qualification keys through `/api/agent/routing-qualification-keys`, or in Settings under
  Qualification keys. Catalog entries hold keys, and a task requirement can name keys that a
  candidate's entry must hold. Retiring a key in use is refused with
  `routing_qualification_key_in_use`. Changing an entry's model alias, provider, reasoning tier
  or effort clears its keys unless the same update restates them.
  ([#169](https://github.com/Denissvgn/WorkChord/pull/169))
- **Calibration contract.** Operators can submit, approve and read a versioned calibration
  contract for performance-informed routing (`/api/agent/routing-calibration-contracts`). It
  records sample bounds, decay, a bias review and the approver. Routing still consumes no
  performance history. ([#174](https://github.com/Denissvgn/WorkChord/pull/174))

### MCP behind the frontend proxy

The stock frontend proxy now forwards the original `Host` header, including the port, to
`/api/mcp`. An instance on a published port such as 8480 no longer answers MCP with
`421 Invalid Host header` unless `MCP_ALLOWED_HOSTS` was overridden.
([#149](https://github.com/Denissvgn/WorkChord/pull/149))

### Reactivation check

The delivery worker process also checks postponed tasks' date requirements every 15 minutes.
No new process is needed.

## Upgrade notes

### Database migrations

This release adds nine migrations. The schema head moves from `20261124_0024` to
`20261127_0033`. The service applies them on start with the normal upgrade path. Take a
backup first, because most downgrades are refused once the new data exists.

| Revision | What it changes | Downgrade |
| --- | --- | --- |
| `20261126_0025` | Adds `local_first` to model catalog entries, default off. | Allowed. |
| `20261126_0026` | Adds `kind` to review records (default `review`) so an owner override is distinguishable. | Refused while an owner override exists. |
| `20261126_0027` | Creates the postponement and reactivation requirement tables. Existing task statuses are untouched. | Refused while a task is postponed or postponement history exists. |
| `20261126_0028` | Adds runtime instance identity columns to team members and issues each existing member a random identity. | Refused while an identity is recorded. |
| `20261126_0029` | Adds `effort` to model catalog entries; every existing entry becomes `unknown`. Nothing is guessed from keys or aliases. | Refused while an entry records an effort. |
| `20261127_0030` | Lets a task replacement record be a supersession (adds `disposition`; base commit and owner decision become optional for it). Existing rows stay replacements. | Refused while a supersession exists. |
| `20261127_0031` | Creates the qualification key registry and its revision history, and adds `qualification_keys` (default empty) to catalog entries. | Unsupported once a key is declared or held. |
| `20261127_0032` | Creates the calibration contract tables and their revision history. | Refused once a contract exists. |
| `20261127_0033` | Adds `routing_conflict_mode` to projects (`refuse` by default, or `warn`). | Allowed. |

### Routing previews

Routing previews issued before the upgrade fail once with `routing_preview_stale`, because the
routing input digest now includes each catalog entry's qualification keys. Request a fresh
preview.

### Configuration

One new optional setting: `PUBLIC_BASE_URL`, the address people use to open the instance. Source
links to it are stored as relative paths. It is empty by default, and loopback links are always
treated as this instance. `MODEL_AWARE_ROUTING_MODE` and every other setting are unchanged.
Copy the new line from `.env.example` if you keep your own environment file.

### Task status values and clients

`postponed` is a new stored task status. Clients that switch on task status must handle it.
`canceled` and `superseded` are displayed states, not stored statuses: read `displayed_state`
(falling back to `status`). The stored status of a canceled task is unchanged. A saved task view
that filters on status now matches the displayed state.

### Role skill packages

Reinstall `workchord-pm` at 1.21.7, `workchord-worker` at 1.20.4 and `workchord-reviewer` at
1.8.6, and check each SHA-256 digest against the skill catalog entry at 1.23.7. If your workspace
already runs these versions, nothing needs to be reinstalled. Reinstall the Claude Code or
Antigravity adapter if you use one. The setup steps for each runtime are in
[agent team setup](../agent-team-setup.md).

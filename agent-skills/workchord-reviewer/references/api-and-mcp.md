## Configure Without Leaking Secrets

REST uses `WORKCHORD_BASE_URL`, an optional API prefix, and `AGENT_API_KEY`.
Agent routes are normally below `/api`; avoid accidentally constructing
`/api/api/...`.

MCP HTTP normally uses `/api/mcp` and either a bearer token or
`X-Agent-API-Key`; stdio uses `MCP_AGENT_API_KEY`. Use a real enabled reviewer
key, not `AGENT_BOOTSTRAP_API_KEY`. Keep all values in the runtime secret store.

## Use These Operations

| Step | REST/MCP contract | Scope |
| --- | --- | --- |
| Capabilities | `GET /api/agent/capabilities`; `agent_get_capabilities` | any |
| Review queue | `GET /api/agent/me/reviews?limit={n}&cursor={opaque}`; `agent_get_my_reviews(limit, cursor)` | `verification:read` |
| Complete context | `GET /api/agent/tasks/{task_id}/context?assignment_id={assignment_id}`; `agent_get_complete_task_context` | `verification:read` |
| Verdict | `POST /api/agent/me/reviews/verdict`; `agent_submit_review_verdict` | `verification:write` |

Do not call planning, assignment, work, claim, run, discovery, or recovery
operations. They belong to the PM and workers, and the reviewer scope preset
does not grant them.

## Send A Verdict

Send one `AgentReviewVerdict`:

- `assignment_id`: the review assignment from your queue;
- `verdict`: `pass` for Accept or `reject` for Request changes;
- `expected_task_version`: the task version you reviewed;
- `evidence`: at most 100 bounded fields, one result per criterion plus checks
  and limitations;
- `reason`: required for `reject`; name the failed criteria;
- `rework_actor_id`: required for `reject`; the worker who takes the rework;
- `rework_queue_rank`: optional position in that worker's queue.

REST sends `Idempotency-Key`, `X-Agent-Rationale`, and `X-Correlation-ID`
headers. MCP takes `idempotency_key`, `rationale`, and `correlation_id`
arguments. Derive the idempotency key from the assignment, task version, and
verdict so an exact retry replays the same receipt.

## Read The Response

The response holds `review_assignment` (now fulfilled), `task` (Accepted as
`closed`, or rework as `active`), and `rework_assignment` for a rejection.
Replace every cached version with these values. Report the task status, the
rework owner, and the queue rank to the PM in your final message.
